### Section: Contact Management - Property-Contact Linking (Line ~449-472)

**REPLACE entire section with:**

```markdown
### Property-Contact Linking

Properties support **multiple contacts** (Many-to-Many relationship). When creating a property, you can:

1. **Link to existing contacts** (provide array of `id`s):

```json
{
  "title": "Beautiful Villa",
  "contacts": [
    { "id": 123 },
    { "id": 456 }
  ]
}
```

2. **Create new contacts** (provide contact details):

```json
{
  "title": "Beautiful Villa",
  "contacts": [
    {
      "name": "John Doe (Owner)",
      "email": "john@example.com",
      "phone": "+351 123456789",
      "notes": "Property owner - available weekdays"
    },
    {
      "name": "Jane Smith (Agent)",
      "email": "jane@agency.com",
      "phone": "+351 987654321",
      "notes": "Real estate agent - available anytime"
    }
  ]
}
```

3. **Mix existing and new contacts**:

```json
{
  "title": "Beautiful Villa",
  "contacts": [
    { "id": 123 },  // Existing contact
    {               // New contact
      "name": "New Agent",
      "email": "agent@example.com",
      "phone": "+351 555555555"
    }
  ]
}
```

**Transaction Safety**: Property creation with new contacts is wrapped in a transaction. If property creation fails, no contacts are created (automatic rollback).

**Validation**: When linking existing contacts, system validates:
- All contacts exist
- All contacts belong to the requesting user
- Error code: `CONTACT_ACCESS_DENIED` if any contact is not owned by user

**Minimum Requirement**: At least one contact must be provided when creating a property.
```

### Section: Frontend Integration - Submit Logic (Line ~1358)

**UPDATE:**

```typescript
const handleSubmit = async (e: Event) => {
    e.preventDefault();

    // Validate at least one contact
    const contactsPayload = useExistingContacts
        ? selectedContactIds.map(id => ({ id }))
        : newContacts.filter(c => c.name && c.email && c.phone);

    if (contactsPayload.length === 0) {
        errorMessage = 'At least one contact is required';
        return;
    }

    const payload = {
        ...property,
        contacts: contactsPayload  // Changed from singular 'contact'
    };

    const response = await apiClient.post<PropertyDTO>('/properties', payload);

    if (response.data.success) {
        const propertyId = response.data.data.id;

        if (selectedImages.length > 0) {
            await uploadImages(propertyId);
        }

        goto(`/properties/${propertyId}`);
    } else {
        // Handle errors
        errorMessage = response.data.error?.message;
    }
};
```

## Summary of Key Changes

1. **Relationship**: Property ↔ Contact changed from **Many:1** to **Many:Many**
2. **Database**: `contact_id` field removed, join table `property_contacts` created automatically
3. **API**: `contact` (singular) → `contacts` (array) in requests/responses
4. **Frontend**: Multi-select UI for contacts instead of single dropdown
5. **Validation**: "At least one contact required" instead of "Contact ID required"
6. **Benefits**:
   - Multiple contact persons per property (owner, agent, manager)
   - Same contact reusable across multiple properties
   - More flexible contact management
